## 3. 已由代码确认的问题

### P0：尺寸标注不关联组件实际尺寸

`dimension` 对象仅保存自身 `w` 和 `text`；创建时默认为 1000，二者分别编辑。对象结构没有组件引用或尺寸方向字段，改动组件宽高、位置不会同步尺寸标注。当前符号是水平尺寸线，用户可以手动旋转对象，但没有宽度/高度关联操作。尺寸标签没有自动追加 mm。

### P0：没有 SVG 文件导出入口

代码有 `serializeExportSvg()`，但目前只被 PNG 导出流程调用；界面没有 SVG 按钮、下载行为或独立 SVG 输出。故现有程序不提供可保存的 SVG 文件。

### P1：组件属性面板提供了部分不生效的设置

属性面板为所有组件都显示开启方向、开启类型和玻璃选项。但 `componentSVG()` 只在特定 kind 中读取方向/开启类型；上悬/下悬、双扇、提拉、百叶、固定和推拉模板中的部分设置不会影响图形。`o.glass` 没有被组件绘制函数使用，因此单玻/中空双玻/钢化玻璃选项不改变当前示意图。

### P1：线宽缺少层级

组件的外框线、扇框线、玻璃线等默认全部为黑色 1；尺寸线单独默认为 2。各线使用 `vector-effect="non-scaling-stroke"`，所以在编辑画布缩放时线条屏幕粗细保持不变。实际打印物理线宽仍需在 PDF/纸张输出中测量，不能仅凭屏幕像素判断。

### P1：无法用画布边角手柄缩放组件

选择框绘制了两个圆形手柄，但选择框和手柄设置了 `pointer-events:none`，事件处理没有尺寸拖拽逻辑。组件尺寸可通过右侧宽度/高度字段修改；如果保留手柄视觉，应让其可操作或移除，以免造成误解。

### P2：拼角线对所有组件默认生效

只要 `joint` 为 45°且图层显示，绘图函数就会对每个门窗 kind 添加四条由外角连向玻璃边界的对角线。该线并非每种门窗在每种示意图中都必需，且在百叶、推拉组件上可能显得多余。是否默认关闭属于制图风格选择，不应伪称标准要求。

## 4. 需要运行输出才能确认的问题

- W010、D006 中央扇料在不同宽高比例、PNG 尺寸和浏览器缩放下是否仍易分辨；代码表明当前没有前后扇的交叠层次，但视觉严重程度需看实际渲染。
- 蓝色框扇填充与白色玻璃在透明/白底 PNG、SVG、打印 PDF 中的实际对比与边缘质量。
- PNG 最大边长限制、透明边缘、字体回退与长尺寸文字是否有裁切或模糊。
- 浏览器打印的页面缩放、页边距、线宽和图形是否受窗口/纸型影响。当前打印样式没有 `@page` 纸型或明确比例控制。
- 新的中英文顶部名称在窄屏下是否挤压按钮；本次名称变更没有改布局规则。

## 5. 需要人工按具体制图用途判断的事项

- 本软件主要表达门窗立面示意，还是还要表达平面/轨道剖面？两轨推拉的轨道关系在不同视图中的画法不同。
- 开启符号是否采用当前折线/箭头表达，是否要统一门、窗、上悬、下悬符号。
- 百叶图示是否需要玻璃边界；默认 45°拼角线是否应对全部组件显示。
- 输出应遵循的纸张、打印比例和物理线宽没有由需求指定；本报告不自行指定国家标准、比例或线宽数值。
- 尺寸关联的交互：建议选中一个组件后点击“尺寸”创建关联宽度标注；在尺寸属性中切换宽度/高度方向。标注随组件移动和改尺寸更新；删除目标组件时关联标注删除或转为普通尺寸需确定。该交互会影响既有尺寸对象行为，进入实现前需确认。

## 6. 修改建议与优先级

| 优先级 | 建议 | 范围 |
|---|---|---|
| P0 | 增加 SVG 直接下载，复用现有 SVG 序列化与擦除遮罩，避免重复绘图逻辑 | 导出入口与下载，不改对象结构 |
| P0 | 按确认后的交互实现关联宽/高尺寸，并在移动、改宽高、复制、删除、撤销重做中验证关联生命周期 | 尺寸对象与属性面板；先确定删除目标时的行为 |
| P1 | 只为对应 kind 显示有效开启选项；对当前没有图形差异的玻璃选项，隐藏/标记为暂不影响示意，避免误导 | 属性面板，保留 kind/ID |
| P1 | 让 W010/D006 的双扇前后关系在示意图中更清楚；不擅自增加轨道截面或生产细节 | 仅改已有 `sliding` / `slidingDoor` 模板 |
| P1 | 用真实浏览器比较屏幕与 PNG/SVG/PDF 输出后，再决定是否调整线宽层级和打印缩放 | 不预设未经确认的物理线宽/比例 |
| P2 | 根据用户目标视图确认拼角线、百叶玻璃边界与门窗开启符号 | 人工制图取舍，不按猜测批量改 |

## 7. 可能影响现有功能的风险

- 修改 `componentSVG()` 会同时影响画布显示、打印和 PNG/SVG 导出；需对 14 个原 ID 全量截图/渲染检查。
- 新增尺寸关联后，移动、改宽高、复制、删除、组合、撤销/重做都会触及对象状态；关联标注不能意外改变原有自由尺寸行为。
- 调整 `vector-effect`、根 SVG 宽高或导出比例可能影响 PNG 清晰度、透明边缘和 PDF 实际尺寸。
- 增加 SVG 下载按钮会占据顶部空间；需验证现有窄屏工具栏和导出按钮仍可达。
- 内部 kind 与组件 ID 被其他交互使用，本次应保持 W001–W008、W010、D001、D003–D006 不变。

## 阶段二实施与验证记录

以下是基于上述基线审查的阶段二结果；第 3、4、6 节中的问题与建议描述的是修改前状态，不代表当前分支仍未处理。

### 已实施

- 更新组件属性面板：只显示当前组件绘制逻辑实际支持的开启方向/开启类型选项；玻璃类型保留为配置记录，并明确提示它不会改变当前二维立面示意，避免把无视觉效果的字段误认为已改变图纸。
- 增加“宽度尺寸”和“高度尺寸”两个入口。选中组件时建立关联，标注值随组件宽高、位置、旋转及镜像方向更新；可调整偏移。复制组件会复制并重连关联标注，删除组件会级联删除关联标注，撤销可恢复；未选组件时仍可创建独立尺寸线。
- 增加 SVG 直接下载，沿用现有 SVG 序列化和擦除遮罩；保留透明 PNG、白底 PNG 和浏览器打印 PDF。
- 14 个现有组件的 ID、kind 和绘制模板均保留。未改动 W010/D006 的轨道/前后扇画法、拼角线默认值和组件 1 px 默认线宽：需求未指定视图方向或物理打印比例，且此前明确要求组件框线默认黑色 1 px；贸然改变会把制图判断伪装成标准结论。相关视觉取舍仍需按实际出图用途确认。
- 修复高度尺寸对象 SVG 变换中心与其竖向尺寸范围不一致的问题，确保高度标注的定位/旋转使用正确的包围尺寸。
- 补齐镜像后的关联尺寸方向：组件水平/垂直翻转后，标注线朝组件方向延伸；调整关联标注偏移时按镜像后的局部法线计算。

### 自动化浏览器回归

通过隔离配置文件启动的 Chrome（未关闭或控制用户现有浏览器），以 1440×1000 桌面视口运行单文件页面。`tests/v1.1-smoke.mjs` 全部通过：

- 原 14 个门窗组件均可通过组件库创建，且生成非空 SVG 图形。
- 图层显隐更新实际 SVG；关联宽/高标注创建、改组件宽高/位置/旋转、复制重连、删除级联及撤销恢复；水平和垂直翻转均验证标注线反向延伸。
- 基础形状创建、复制、组合/取消组合、翻转、撤销/重做，以及橡皮擦属性面板。
- SVG、白底 PNG、透明 PNG 文件下载；栅格抽样确认白底 PNG 不透明、透明 PNG 保留 alpha。
- 浏览器打印接口生成 PDF，文件头为 `%PDF-`；页面未捕获到控制台错误。

### 尚未确认

- 没有做实体打印或不同纸型下的物理线宽/比例测量；PDF 自动生成仅验证文件生成，不代表打印比例或排版符合特定规范。
